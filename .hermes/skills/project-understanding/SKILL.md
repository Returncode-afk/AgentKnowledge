# 项目理解与导航方法论

## 核心原则

1. **先导航后动手** - 先理解项目全貌，再定位具体代码
2. **文档优先** - 文档是项目的地图，代码是细节
3. **层层递进** - 从整体到局部，从概览到细节
4. **文档闭环** - 理解项目后主动创建/更新文档

---

## 一、项目发现策略

### 第一步：识别项目类型

```
判断项目类型：
│
├── package.json → Node.js项目
├── pyproject.toml / requirements.txt → Python项目
├── Cargo.toml → Rust项目
├── pom.xml → Java项目
├── go.mod → Go项目
│
└── 混合项目 → 多语言项目
```

### 第二步：查找项目文档

**标准文档优先级**（AI会自动发现）：
1. `CLAUDE.md` - AI开发者指南（面向AI的提示）
2. `README.md` - 项目总览
3. `CONTRIBUTING.md` - 贡献指南
4. `ARCHITECTURE.md` - 架构文档
5. `docs/` - 文档目录

### 第三步：理解项目结构

```
项目结构分析方法：
│
├── 根目录文件 → 项目级配置和入口
│
├── 主要子目录 → 功能模块划分
│   ├── src/ 或 lib/ → 源代码
│   ├── test/ 或 tests/ → 测试
│   ├── docs/ → 文档
│   ├── scripts/ → 脚本工具
│   └── 配置目录 → config/, settings/
│
└── 配置文件 → 技术栈和依赖
```

## 二、核心代码定位

### 快速定位关键代码

| 想找什么 | 搜索策略 |
|----------|----------|
| API入口 | 搜索 `app.use`、`@app.route`、`def.*request` |
| 核心算法 | 搜索 `def algorithm`、`function process`、`class.*Engine` |
| 数据模型 | 搜索 `class.*Model`、`schema`、`interface` |
| 配置管理 | 搜索 `config`、`settings`、`env` |
| 异步任务 | 搜索 `async`、`await`、`Promise`、`spawn` |

### 追踪数据流

```
数据流追踪步骤：
│
1. 找到入口点（API endpoint / main函数）
│
2. 沿调用链追踪
│   ├── 函数调用 →
│   ├── 事件触发 →
│   └── 消息传递 →
│
3. 找到终点（数据库 / 文件系统 / API响应）
```

## 三、算法发现策略

### 通用算法文件特征

| 算法类型 | 常见位置 | 命名特征 |
|----------|----------|----------|
| 搜索/排序 | `utils.py`、`helpers.js` | `search`、`sort`、`find` |
| 解析器 | `parser/`、`parse.py` | `parse`、`extract`、`decode` |
| 验证器 | `validator.py`、`schema.js` | `validate`、`check`、`verify` |
| 转换器 | `converter.py`、`transform.js` | `convert`、`transform`、`map` |
| 分发/路由 | `dispatcher.py`、`router.js` | `dispatch`、`route` |

### 算法识别模式

```
核心算法特征：
│
├── 复杂条件判断 → 业务逻辑
├── 循环+累积 → 数据处理
├── 递归 → 树/图遍历
├── 正则表达式 → 模式匹配
└── 外部调用 → 集成逻辑
```

## 五、联动分析

### 修改前的联动检查

```
当你需要修改代码时，问自己：
│
├── 这个函数/变量在哪里被调用？
│   └── 搜索所有引用
│
├── 哪些视图/组件依赖这个数据？
│   └── 追踪数据消费者
│
├── 修改会影响哪些功能？
│   └── 考虑边界情况
│
└── 需要重启服务吗？
    └── 动态语言 vs 编译语言
```

### 调用链追踪命令

```bash
# 搜索函数定义
grep -r "functionName" --include="*.py"

# 搜索调用点
grep -rn "functionName(" --include="*.py"
```

## 六、调试方法

### 七步调试法

1. **收集信息** - 错误信息、复现步骤、预期vs实际
2. **缩小范围** - 前端/后端、数据/UI、单点/系统
3. **追踪数据流** - 从入口到出口
4. **检查状态** - 文件系统、数据库、缓存
5. **定位代码** - 找到问题所在
6. **实施修复** - 考虑联动影响
7. **验证修复** - 测试所有相关功能

### 小样本测试法

```
当调试复杂逻辑时：
│
1. 创建小规模模拟样本
2. 编写独立测试脚本
3. 逐步验证
```

## 九、文档生成工作流

当理解一个项目后，按以下顺序生成文档：

```
1. 先创建 README.md（项目总览）
   │
   ├── 项目简介
   ├── 文档索引
   ├── 快速开始
   └── 项目结构

2. 再创建 CLAUDE.md（AI开发者指南）
   │
   ├── 文档索引（指向其他文档）
   ├── 核心算法位置表
   ├── 关键配置表
   └── 开发约定

3. 然后创建 ARCHITECTURE.md（架构）
   │
   ├── 系统分层图
   ├── 核心模块表
   └── 数据流图

4. 接着创建 ALGORITHMS.md（算法）
   │
   ├── 算法概览表
   ├── 核心算法详解
   └── 算法对比表

5. 最后创建 PROJECT_MAP.md（关系）
   │
   ├── 子项目概览表
   ├── 依赖关系图
   └── 详细说明

6. 子模块创建 MODULE.md
   │
   ├── 模块概述
   ├── 核心文件表
   └── API接口
```
