# Personal Knowledge Base AGENTS

## 作用

定义所有 Agent 的操作规则，保持工具兼容性。支持 Claude、GPT、Claude Code 等各种 AI 工具。

## 设计原则

- **统一入口**：所有输入必须通过 Notes/ 进入系统
- **确认机制**：AI 建议，用户拍板（避免分类错误）
- **链接精简**：质量优于数量，减少维护负担
- **对话价值**：Conversation/ 目录保存 AI 对话知识
- **产出导向**：知识必须能转化为实际产出
- **工具无关**：通过本文件保持系统兼容性

## 三大核心操作流程

### 1. Ingest（入库）流程

当用户说"处理一下 Notes/" 或添加新内容时执行：

**第一步：扫描方案**
扫描 Notes/ 下所有未处理内容，生成处理方案表：

| 文件 | 建议放哪 | 怎么处理 | 为什么 |
|------|----------|----------|--------|
| xxx.md | Knowledge/个人成长 | 写摘要+创建页面 | 方法论文档 |

**第二步：用户确认**
用户查看表格并确认，AI 不自行执行

**第三步：内容分发**
按内容性质判断目标目录：

| 内容类型 | 目标目录 |
|----------|----------|
| 软件工具/代码技巧 | Software/ |
| 投资/保险/健康/生活 | LifeOS/ |
| 方法论/读书笔记/概念 | Knowledge/ |
| 内容创作方法论 | Writing/Knowledge/ |
| 选题素材/草稿 | Writing/内容素材/ |
| 无法判断 | 留在 Notes/ 等待人工处理 |

**第四步：内容加工**
- 写摘要
- 创建/更新 Wiki 概念页面
- 补充交叉引用

**第五步：清理**
- 原始文件从 Notes/ 删除
- 记录到处理日志

---

### 2. Query（查询）流程

当用户提问或需要查找知识时执行：

**第一步：理解问题**
分析用户问题的核心需求

**第二步：目录搜索**
按优先级在相关目录搜索：
1. Knowledge/ - 方法论和概念
2. LifeOS/ - 行动和实践
3. Software/ - 工具技巧
4. Writing/ - 产出内容

**第三步：综合回答**
综合多篇文件给出答案，标注来源

**第四步：反哺机制**
搜索过程中发现内容互补但未链接的文件，建议补链

**第五步：确认执行**
用户确认后执行链接补充

---

### 3. Lint（健康检查）流程

定期或按需执行，检查知识库健康状态：

**检查项：**

| 检查项 | 说明 | 处理方式 |
|--------|------|----------|
| 孤立页面 | 没有任何链接指向的文件 | 用户决定删除或补链 |
| 过时内容 | 超过90天未更新的文件 | 用户决定更新或删除 |
| 缺失引用 | 讲同一概念但未互相链接的文件 | 建议添加链接 |
| Notes/ 积压 | 超过7天未处理的输入 | 提醒用户处理 |

**执行方式：**
- 按目录分别运行（Knowledge/ 是重点，Software/ 可跳过）
- 生成报告但不自动修改
- 用户根据报告手动优化

## 交叉引用规则

### 链接原则

只建立最强关联，不追求覆盖率

### 适用场景

- 两篇文章内容互补（如：获客方法论 + 产品打磨哲学）
- 理论和实践配对（如：同理心理论 + 同理心实践）
- 读书笔记和应用思考配对（如：《深度工作》+ 时间管理）
- 人物和方法论配对（如：乔布斯的管理课 + 领导力）

### 格式

在文件末尾添加：

```markdown
## 相关页面

- [[概念名]] - 简短说明
```

## 各目录处理逻辑

### Notes/（输入层）

- **性质**：临时存放，所有内容的中转站
- **处理**：定期清理，超过7天未处理则提醒
- **禁止**：不允许永久保存内容

### Knowledge/（知识层）

- **性质**：方法论、读书笔记、概念解析
- **来源**：Notes/ 分发、网页剪藏、AI 对话
- **处理**：重点维护，需要定期 Lint

### Software/（技能层）

- **性质**：工具技巧、开发思考、操作手册
- **来源**：工具使用经验、技术文档
- **处理**：可跳过 Lint，以实用为准

### LifeOS/（行动层）

- **性质**：投资笔记、健康计划、生活事务
- **来源**：实际操作记录、决策笔记
- **处理**：强调落地执行，定期更新

### Writing/（产出层）

- **性质**：视频脚本、文章草稿、内容素材
- **来源**：Knowledge 转化、灵感记录
- **处理**：最终产出，标记创作状态

### wiki/（概念层）

- **性质**：自动从 sources/ 编译生成的概念页面
- **来源**：sources/ 中的文档通过 llm-wiki-compiler 生成
- **处理**：自动维护，与 HiClaw 记忆系统同步

### sources/（原始文档）

- **性质**：原始文档存储，与 Wiki 编译系统共享
- **来源**：用户添加的 Markdown、TXT、PDF 转换内容
- **处理**：Wiki 编译的原材料，定期编译到 wiki/

## Wiki 与 HiClaw 集成

### 工作流程

```
用户添加文档 → sources/ → llm-wiki-compiler → wiki/concepts/
                                                        ↓
                                                  wiki/sync/
                                                        ↓
                                                  HiClaw 记忆系统
```

### 同步机制

- Wiki 编译后自动同步到 `wiki/sync/` 目录
- HiClaw 通过 API 读取 `wiki/sync/` 内容
- 概念页面支持双向链接

### HiClaw 访问方式

```bash
# 列出同步的文件
curl -s http://localhost:18090/api/wiki/sync/files \
  -H "Authorization: Bearer hiclaw-knowledge-api"

# 读取具体文件
curl -s http://localhost:18090/api/wiki/sync/概念名.md \
  -H "Authorization: Bearer hiclaw-knowledge-api"
```
